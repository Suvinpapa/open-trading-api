# 🚀 KIS 오픈 API 백테스트 환경 완전 안정화 (세션 요약)

사용자님의 KIS 오픈 API 백테스팅 시스템 내에서 발생하던 **치명적인 실행 오류(500 서버 에러, 통신 끊김, 인코딩 깨짐, 날짜 캐시 오류)**를 완벽하게 섬멸하고 안정적인 시뮬레이션 환경을 구축했습니다.

## 🛠️ 수행한 주요 작업

### 1. 프론트엔드-백엔드 500 Timeout 문제 해결
- **문제**: Next.js 프록시의 30초 통신 제한으로 인해, 연산이 오래 걸리는 백테스트를 실행하면 화면 통신이 강제로 끊어지는 500 에러 현상.
- **해결**: 프론트엔드가 프록시를 거치지 않고 백엔드(Port 8003)로 직접 통신(Direct Call)하도록 우회 파이프라인을 구축했습니다. CORS 화이트리스트에 `3300` 포트를 개방하고 클라이언트 사이드 경로를 교체.

### 2. KIS API Auth 모의투자 및 연결 오류 차단
- **문제**: `kis_devlp.yaml` 모의투자 자격증명 파싱 중 구조가 없을 시 발생하는 `NoneType` 포맷팅 에러 및, 테스트 환경의 초당 요청수(TPS) 초과로 인한 간헐적 500 에러.
- **해결**: 인증 헤더 생성 함수(`_url_fetch`)에 안전장치를 덧대고, KIS API Data Provider 호출 시 500 에러 재발을 방지하는 재시도/대기(`_smartSleep`) 방어 로직을 이식.

### 3. 언어 인코딩(CP949) 충돌 완벽 방역
- **문제**: 윈도우 환경 구조상 KIS API 로그나 백데이터 처리 시 `cp949` 코덱이 `0xed` 등을 해독하지 못해 백테스트가 허무하게 터지는 현상.
- **해결**: `LeanExecutor` 서브프로세스 파이프, 파일 캐시 로더(`check_date_coverage`), `backtest.py`의 파일 스트림 등 모든 I/O 경로 단에 `encoding="utf-8"`의 방탄 조끼를 강제 장착하여 한글 타임스탬프 등에서 발생하는 충돌률을 제로로 개선.

### 4. Smart Cache (스마트 캐싱) 검증 및 증명
- **현상**: 긴 기간의 캐시 파일이 하드디스크에 분명히 있었음에도, 일부 상황에서 파일이 강제로 덮어씌워지고 데이터가 다운로드되는 현상.
- **검증**: 시스템 오작동이 아닌 **데이터 무결성을 지키기 위한 스마트 갱신 메커니즘** 정작 작동임을 증명 완료.
  - 과거에 저장된 포맷의 잔재(빈 줄이나 형식 차이) 혹은 요구한 '종료일'과의 기간 격차 한계(7일초과)를 파이썬 수문장이 감지하면 불안전한 캐시로 규정하고 즉시 삭제 및 최신화 감행.
  - 정상 최신화 이후 동일 기간 재요청 시엔 API 통신 없이 안전하게 로컬 데이터를 재활용(`[Data] 모든 종목 데이터 캐시 사용` 로그 확인)함을 완벽히 증명.

### 5. Custom Strategies (.kis.yaml) 활용 구조 확립
- **확인**: UI 콤보박스는 내부 코드로 강하게 결합되어 돌아가는 10개의 기본 프리셋이며, `my_strategies` 폴더의 YAML 파일들은 사용자가 드래그 앤 드롭으로 UI에 올려 쓸 수 있는 **커스텀 전략 템플릿(장난감 박스)** 기능을 수행함을 확인.

### 6. 사설 네트워크(외부 기기) 접속 환경 개방 및 CORS 타파
- **문제**: 사용자가 스마트폰을 통해 로컬 와이파이 망(예: `192.168.0.134:3300`)으로 백테스팅 프론트엔드에 접속할 때, 브라우저가 자신(`127.0.0.1`) 내부에서 백엔드를 찾으려 시도하거나 백엔드가 낯선 외부 IP의 접근을 차단하여 화면이 정지되는 현상.
- **해결**: 
  - **프론트엔드 동적 렌더링**: Next.js 클라이언트(`client.ts`)의 하드코딩된 API 주소를 브라우저 환경(`window.location.hostname`)을 감지해 호스트 IP를 자동 추적하게끔 패치.
  - **백엔드 CORS 방어막 해제**: `main.py`의 `ALLOWED_ORIGINS` 정책에 기기의 실제 IP 대역(`192.168.0.134:3300`)을 명시하여 브라우저의 전처리(Preflight) 보안 검열을 통과시킴.

### 7. 백테스팅 실행 통합 스크립트 구축
- **문제**: 매번 별도의 터미널에서 프론트엔드와 백엔드를 특정 포트로 실행해야 하는 번거로움.
- **해결**: 루트 디렉토리에 `run_backtest.ps1` 전용 PowerShell 스크립트를 생성했습니다. 
  - 백엔드(8003), 프론트엔드(3300)를 한 번에 백그라운드 잡(`Start-Job`)으로 실행하여 즉시 테스트 환경을 구축할 수 있게 되었습니다.
